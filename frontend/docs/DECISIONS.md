# Решения и открытые вопросы Slotvio

Документ отделяет зафиксированные решения от деталей, которые пока нельзя домысливать.

## Подтверждённые решения

| Тема | Решение |
|---|---|
| Продукт | Slotvio — web/PWA для записи к независимым мастерам |
| Роли | Только Мастер и Клиент; роли Салон нет |
| Режимы | Одна учётная запись может работать в двух режимах; клиент может стать мастером |
| Кабинет мастера | Планер, День, Профиль; начальная вкладка — День |
| Кабинет клиента | Поиск, Мои записи, Профиль; начальная вкладка — Поиск |
| Поиск | Одно универсальное поле; отдельные фильтры направления и формата работы отсутствуют |
| Формат работы | Студия, дома, выезд к клиенту; хранится в профиле |
| Карта | Не входит в MVP; возможная будущая возможность |
| Календарь | Собственный стилизованный виджет, несколько отдельных дат, быстрый выбор, периоды дня и точное время |
| Выходные | Ближайшие предстоящие суббота и воскресенье |
| Попапы | Календарь и выбор города взаимоисключающие; выбранный город сохраняется |
| Уведомления | Напоминания за 24 и 2 часа до визита |
| Записи | Для MVP автоматически подтверждаются |
| Предложения | Раздел «Предложения» доступен мастеру и клиенту |
| Стек | Frontend React/Vite/JavaScript/CSS; backend отдельно разрабатывается на Go |

## Открытые вопросы

Не блокируют работу, если текущая задача не зависит от них. Не заполнять предположениями.

- API-контракт и способ интеграции frontend с Go backend.
- Провайдер и точный сценарий аутентификации; механизм хранения пользовательских данных между сессиями.
- Канал доставки напоминаний (push, Telegram, email и т. п.).
- Географические/ценовые правила: валюта, налоги, представление стоимости и точная логика фильтра «ближайшая доступность».
- Детали отмены, переноса, длительности и конфликтов записей, включая правила доступности слотов.
- Содержание настроек аккаунта и точное взаимодействие переключения ролей.
- Детальная схема раздела «Предложения» и путь обработки заметок разработчиками.
- Правила рейтинга и модерации, а также постоянный источник изображений/контента мастеров.
- Точный список городов-спутников за пределами примеров в коде и способ их обновления.

## Идеи для календаря (пока не внедрены)

- Закрепить панель с кнопками «Сбросить» и «Готово» у нижнего края окна календаря, чтобы она оставалась видимой при прокрутке.
- Сделать область с остальным содержимым календаря прокручиваемой отдельно от панели кнопок.
- Ориентир — приложенный пользователем скриншот календаря. Это предложение по поведению и компоновке, а не требование к текущей реализации.

## Наблюдения по текущему репозиторию (6 ноября 2026)

- `src/App.jsx` немедленно возвращает `<ClientCabinet />`; следующие возвраты `<MasterCabinet />` и UI выбора роли/входа недостижимы. Это состояние прототипа; не считайте его утверждённым роутингом или готовой авторизацией.
- В `src/ClientCabinet.jsx` есть демонстрационные мастера и список городов; это mock-данные, не утверждённый backend-контракт или полный справочник.
- Доступны `MasterCabinet.jsx`, `ClientCabinet.jsx` и соответствующие CSS файлы. Сверяйте требования с фактическим кодом до изменения.
- В переписке были изображения-референсы, но их содержание не доступно в дереве проекта; документированы подтверждённые словами требования и выбранный визуальный принцип.
